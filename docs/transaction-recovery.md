# 钱包替换交易恢复

原实现只追踪一个 localStorage pending 对象，旧哈希没有回执时永久等待，且购买、领奖、退款共用阻塞。新实现保留原存储键并迁移为 version 6，按钱包记录多笔交易；购买与授权继续防止重复购买，领奖、退款仅拦截相同场次、相同操作且期号重叠的待确认请求。切换钱包不继承另一钱包的阻塞。

广播时保存起始区块、原始请求和返回哈希，能读取到交易时绑定实际外层 nonce。核查原哈希及用户提供的替换哈希；nonce 被链上消耗后，通过历史 nonce 二分定位区块，再核对发送人、网络、nonce 和规范链回执。相同调用的加速交易继续校验 PurchaseResult，包括实际份数及扣款；取消和其他替换只解除原单等待，不能算购买成功。授权等待通过原哈希查询持久化终态，仅 confirmed 允许继续购买。

自动恢复不会因 mempool 查不到交易或超时而宣称成功。旧记录没有实际 nonce 绑定时，尤其是 MetaMask 包装交易 / EIP-7702 授权消耗 nonce，无法可靠证明取消的情况保留“结果待核实”。用户可以填写最新哈希核对；无效地址、网络、nonce 或哈希不覆盖已有记录。

“移出等待”是用户明确选择的本地操作，记录状态为 unverified 并保留交易链接，不能撤销链上交易，也不能触发授权后的自动购买。钱包已广播但尚未处理的低 nonce 仍可能阻挡后续交易上链，需要在钱包加速或取消；移出页面等待不能改变链的 nonce 顺序。

交易读取每两秒进行，较重的替换发现每笔最多每十秒一次；手动“重新核查”可立即发现。全区块读取仅允许明确的数值区块，复用现有 RPC 并发和队列限制。多个标签页的状态更新使用同一 Web Lock，并在写入前比较记录，避免旧核查覆盖新请求。

回归：`node --test test/bem-sparkdraw-recovery.test.mjs test/bem-sparkdraw-player.test.mjs test/bem-wallet-transaction-envelope.test.mjs test/bem-rpc-concurrency.test.mjs`。覆盖替换、取消、部分成交、旧记录、无哈希、错误哈希、短暂断网、非规范链回执、钱包切换、独立领取及重复领取。
